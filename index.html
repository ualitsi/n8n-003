Resumen

Esta práctica introduce la autenticación con servicios externos mediante el sistema de credenciales de n8n, y realiza la primera integración con un servicio persistente: Google Sheets. Se amplía la lógica de negocio más allá del nodo IF con el nodo Switch (enrutamiento de múltiples ramas) y el nodo Merge (fusión de flujos de datos). A lo largo de la sesión se construye un flujo de trabajo guiado que clasifica chistes por categoría y los escribe en hojas separadas de un documento de Google Sheets, y se resuelven varios ejercicios de complejidad creciente para consolidar los conceptos.

1. Objetivos de la Práctica

Esta tercera práctica representa un paso crucial hacia la construcción de automatizaciones de nivel profesional. Se abandonan las APIs públicas sin estado para realizar la primera integración con un servicio persistente y de uso extendido: Google Sheets. Este proceso introducirá el concepto fundamental de la gestión de credenciales. Además, se ampliarán las capacidades de lógica de negocio de los flujos de trabajo, superando la bifurcación simple del nodo IF para implementar enrutamientos complejos con múltiples salidas.

Al finalizar esta sesión, el estudiante habrá desarrollado las siguientes competencias:

  • Gestión de Autenticación: Comprender el propósito del sistema de credenciales de n8n y configurar con éxito una credencial OAuth 2.0 para interactuar con las APIs de Google.

  • Integración con Servicios de Terceros: Utilizar el nodo de Google Sheets para realizar operaciones de escritura (añadir filas) en una hoja de cálculo, sentando las bases para futuras integraciones con bases de datos y otros servicios SaaS.

  • Lógica de Enrutamiento Avanzada: Implementar el nodo Switch para dirigir el flujo de datos hacia múltiples ramas de ejecución basándose en el valor de un campo, superando la limitación de dos salidas del nodo IF.

  • Fusión de Flujos de Datos: Utilizar el nodo Merge para recombinar múltiples ramas de ejecución en un único flujo de datos, un patrón esencial para la consolidación de resultados y la continuación de un proceso unificado.

  • Diseño de Flujos de Trabajo Modulares: Construir flujos de trabajo que procesan, enrutan, actúan y consolidan datos de manera estructurada, aplicando los principios de diseño de software a la automatización visual.

2. Fundamentos Teóricos

2.1. Gestión de Credenciales en n8n

Hasta ahora, hemos interactuado exclusivamente con APIs públicas que no requieren autenticación. Sin embargo, la gran mayoría de los servicios (Google Sheets, Slack, bases de datos, etc.) necesitan verificar la identidad y los permisos del cliente que realiza la solicitud. n8n centraliza y asegura este proceso a través de su sistema de Credenciales.

Una credencial en n8n es un registro seguro que almacena la información de autenticación para un servicio específico (una clave de API, un token de acceso OAuth 2.0, un par de usuario/contraseña, etc.). Almacenar esta información en el gestor de credenciales en lugar de escribirla directamente en los nodos ofrece ventajas críticas:

  • Seguridad: La información sensible se cifra y se almacena de forma centralizada, en lugar de estar visible en el JSON del flujo de trabajo.

  • Reutilización: Una única credencial (por ejemplo, para una cuenta de Google) puede ser utilizada en docenas de flujos de trabajo y nodos diferentes. Si la credencial necesita ser actualizada, solo se cambia en un lugar.

  • Abstracción: El desarrollador del flujo de trabajo no necesita gestionar la complejidad de los flujos de autenticación como OAuth 2.0. Simplemente selecciona la credencial apropiada y n8n se encarga del resto.

Para esta práctica, crearemos una credencial de Google usando el protocolo OAuth 2.0, que es un estándar de la industria para la autorización delegada. Esto implica un proceso único en la Consola de Google Cloud para autorizar a nuestra instancia de n8n a actuar en nuestro nombre en servicios como Google Sheets.

2.2. Lógica de Múltiples Ramas: El Nodo Switch

En la práctica anterior, el nodo IF nos permitió crear lógica condicional con dos salidas: true y false. Sin embargo, muchos problemas del mundo real requieren más de dos caminos. Por ejemplo, clasificar un ticket de soporte por prioridad (Baja, Media, Alta, Urgente) o procesar pedidos según el país de envío. Para estos escenarios, encadenar múltiples nodos IF sería ineficiente y difícil de leer.

El nodo Switch es la solución de n8n para el enrutamiento de múltiples ramas. Funciona de manera similar a una declaración switch en lenguajes de programación. Se configura un campo de "Enrutamiento" (el valor a evaluar, por ejemplo, {{ $json.category }}) y luego se definen múltiples reglas de enrutamiento. Cada regla compara el valor del campo con un valor específico y, si coincide, envía el ítem a su salida correspondiente.

El nodo Switch crea una salida numerada para cada regla (0, 1, 2,…​). También proporciona una salida default (predeterminada) para los ítems que no coinciden con ninguna de las reglas definidas, lo que es crucial para manejar casos inesperados.

2.3. Fusión de Flujos de Datos: El Nodo Merge

Cuando un flujo de trabajo se divide en múltiples ramas (usando IF o Switch), a menudo es necesario volver a unir esas ramas para realizar una acción final común. Por ejemplo, después de procesar pedidos de diferentes países en ramas separadas, es posible que queramos enviar una única notificación de resumen o registrar todos los pedidos procesados en un log.

El nodo Merge está diseñado específicamente para este propósito. Espera a que todas sus entradas conectadas hayan terminado de ejecutarse y luego combina los ítems que reciben en un único flujo de salida. El nodo Merge es altamente configurable y ofrece varios modos de operación para diferentes escenarios de fusión de datos:

  • Append (Anexar): Es el modo más simple. Simplemente toma todos los ítems de la primera entrada, luego todos los de la segunda, y así sucesivamente, y los coloca en un único array de salida.

  • Combine by Position (Combinar por Posición): Une los ítems basándose en su orden. El primer ítem de la entrada 1 se fusiona con el primer ítem de la entrada 2, el segundo con el segundo, etc.

  • Combine by Key (Combinar por Clave): Es el modo más potente. Fusiona ítems de dos entradas que tienen un valor coincidente en un campo clave especificado. Por ejemplo, se podrían combinar datos de clientes de un sistema con datos de pedidos de otro, usando el customer_id como clave de unión.

Para el flujo de trabajo guiado, utilizaremos el modo Append para consolidar los resultados de nuestras diferentes ramas de Switch antes de finalizar el flujo de trabajo. Los modos Combine by Position y Combine by Key se pondrán en práctica en los ejercicios propuestos.

3. Desarrollo del Flujo de Trabajo Guiado

En esta sección, construiremos paso a paso un flujo de trabajo que obtiene chistes de tres categorías diferentes, los clasifica usando un nodo Switch y escribe cada tipo de chiste en una hoja separada dentro de un único documento de Google Sheets. Al finalizar, el flujo quedará listo para ejecutarse de forma manual o programada.

3.1. Paso 1: Preparar el Documento de Google Sheets

  1. Vaya a https://sheets.google.com y cree una nueva hoja de cálculo. Póngale un nombre descriptivo, como "Clasificación de Chistes n8n".

  2. Dentro de este documento, cree tres hojas (pestañas). Renómbrelas a: Programming, Misc y Dark.

  3. En cada una de las tres hojas, añada las siguientes cabeceras en la primera fila: ID, Chiste y Fecha de Procesamiento.

3.2. Paso 2: Configurar las Credenciales de Google (OAuth 2.0)

Este es el paso más complejo, pero solo necesita hacerse una vez. Siga la guía oficial de n8n o un tutorial detallado para configurar las credenciales de Google OAuth. El proceso general es:

  1. Vaya a la https://console.cloud.google.com/.

  2. Cree un nuevo proyecto (o use uno existente).

  3. Habilite la Google Sheets API para ese proyecto.

  4. Habilite la Google Drive API para ese proyecto.

Figure 1. Google Sheets API

  1. Vaya a "Pantalla de consentimiento de OAuth", configúrela como "Externa" y añada su propia dirección de correo electrónico como usuario de prueba.

  2. Vaya a "Credenciales", haga clic en "Crear credenciales" → "ID de cliente de OAuth".

  3. Seleccione "Aplicación web" como tipo.

  4. En n8n, añada un nodo de Google Sheets, haga clic en "Credential" → "Create New". Copie la "URL de redireccionamiento de OAuth" que n8n le proporciona.

Figure 2. URI de redireccionamiento autorizados

  1. Pegue esa URL en el campo "URI de redireccionamiento autorizados" en la Consola de Google Cloud.

Figure 3. Client Credentials Google

  1. Cree las credenciales. Google le proporcionará un ID de cliente y un Secreto de cliente.

  2. Copie y pegue estos dos valores en la ventana de creación de credenciales de n8n y guarde.

  3. n8n le pedirá que inicie sesión con su cuenta de Google para autorizar la conexión.

Figure 4. Example Integration Google Sheets

3.3. Paso 3: Construir el Flujo de Trabajo

  1. Manual Trigger: Comience con un Manual Trigger para facilitar las pruebas.

  2. HTTP Request:

    • Añada un nodo HTTP Request para obtener chistes de múltiples categorías.

    • URL: https://v2.jokeapi.dev/joke/Programming,Misc,Dark?type=single&amount=10

    • Ejecute el nodo y verifique que recibe un array de 10 chistes en el campo jokes.

  3. Split Out:

    • Añada un nodo Split Out para procesar cada chiste individualmente.

    • Field To Split Out: jokes

  1. Switch Node:

    • Añada un nodo Switch para enrutar los chistes.

    • Mode: Rules

    • Routing Field: {{ $json.category }}

    • Routing Rules:

      • Output 0: is equal to → Programming

      • Add Routing Rule

      • Output 1: is equal to → Misc

      • Add Routing Rule

      • Output 2: is equal to → Dark

    • Ejecute el nodo y verifique que los ítems se distribuyen correctamente entre las salidas 0, 1 y 2.

Figure 6. Switch Node

  1. Nodos Google Sheets:

    • Ahora, conecte un nodo Google Sheets a cada una de las tres salidas del Switch.

    • Para la Salida 0 (Programming):

      • Credential: Seleccione la credencial de Google que creó.

      • Operation: Append Row

      • Document: Seleccione su hoja de cálculo "Clasificación de Chistes n8n".

      • Sheet: Seleccione la hoja Programming.

      • Columns:

        • ID: {{ $json.id }}

        • Chiste: {{ $json.joke }}

        • Fecha de Procesamiento: {{ $now }} (variable global de n8n que devuelve la fecha y hora actuales).

    • Para la Salida 1 (Misc):

      • Copie el nodo anterior y conéctelo a la salida 1.

      • Modifique solo el parámetro Sheet para que apunte a la hoja Misc.

    • Para la Salida 2 (Dark):

      • Copie el nodo de nuevo y conéctelo a la salida 2.

      • Modifique el parámetro Sheet para que apunte a la hoja Dark.

  2. Merge Node:

    • Añada un nodo Merge al lienzo.

    • Conecte las salidas de los tres nodos de Google Sheets a la única entrada del nodo Merge.

    • Mode: Append

    • Esto asegurará que el flujo de trabajo continúe solo después de que todas las operaciones de escritura en la hoja de cálculo hayan finalizado.

  3. Ejecución Final:

    • Ejecute el flujo de trabajo completo desde el Manual Trigger.

    • Abra su documento de Google Sheets. Debería ver los chistes distribuidos correctamente en sus respectivas hojas, cada uno con su ID y la fecha de procesamiento.

4. Ejercicios Propuestos

4.1. Ejercicio 1: Consolidación en una Sola Hoja (Dificultad: Baja)

Objetivo: Modificar el flujo de trabajo guiado para que, en lugar de escribir en tres hojas diferentes, escriba todos los chistes en una única hoja llamada "Todos", pero añadiendo una columna que especifique la categoría original.

Requisitos:

  1. Elimine los tres nodos de Google Sheets y el nodo Merge del flujo de trabajo guiado.

  2. Entre cada salida del Switch y el nodo de Google Sheets, añada un nodo Edit Fields (Set) que cree un campo categoria_original con el valor correspondiente ("Programming", "Misc" o "Dark").

  3. Conecte las tres salidas (a través de sus respectivos nodos Edit Fields (Set)) a un único nodo Google Sheets.

  4. Configure este nodo para que escriba en una nueva hoja "Todos" y mapee las columnas ID, Chiste, Fecha de Procesamiento y la nueva categoria_original.

4.2. Ejercicio 2: Clasificación de Productos por Valoración (Dificultad: Media)

Objetivo: Crear un nuevo flujo de trabajo desde cero que analice productos de una API de comercio electrónico de prueba, los clasifique según su valoración y los guarde en diferentes hojas de un documento de Google Sheets.

API a utilizar: Fake Store API (https://fakestoreapi.com/products)

Requisitos:

  1. El flujo de trabajo debe iniciarse con un Manual Trigger.

  2. Use un HTTP Request para obtener todos los productos de la API.

  3. Use un Split Out sobre el campo products (o el array de la respuesta) para procesar cada producto individualmente.

  4. Use un nodo Switch en modo Rules con el Routing Field {{ $json.rating.rate }} para clasificar los productos en tres rangos:

    • Salida 0 ("Top"): una condición is greater than or equal to 4.5.

    • Salida 1 ("Bueno"): dos condiciones combinadas con AND: is greater than or equal to 3.5 y is less than 4.5.

    • Salida 2 ("Regular"): una condición is less than 3.5.

    • (Pista: en el modo Rules, cada salida puede tener varias condiciones. Añada una segunda condición a la Salida 1 y asegúrese de que el operador lógico entre condiciones sea AND).

  5. Cree un Google Sheet llamado "Análisis de Valoraciones" con tres hojas: Top, Bueno y Regular.

  6. Escriba los productos en la hoja correspondiente, incluyendo al menos las columnas ID, Título, Precio y Valoración.

4.3. Ejercicio 3: Gestor de Tareas por Prioridad (Dificultad: Alta)

Objetivo: Crear un flujo de trabajo que obtenga actividades aleatorias, las clasifique por prioridad y tipo, las asigne a diferentes "departamentos" (hojas de cálculo) y registre cada asignación en un log general.

APIs a utilizar: . Para obtener actividades: The Bored API (https://bored-api.appbrewery.com/filter?number=5) . Para almacenar los resultados: Google Sheets

Requisitos:

  1. Use un nodo Schedule Trigger para que se ejecute cada 5 minutos.

  2. Use un HTTP Request para obtener 5 actividades de la Bored API (el endpoint /filter?number=5 devuelve un array de 5 objetos).

  3. Use un Split Out sobre el array de actividades para procesar cada una individualmente.

  4. Añada un nodo Edit Fields (Set) (o Code) que, para cada actividad, genere aleatoriamente un campo priority con uno de los valores "Alta", "Media" o "Baja", y un campo type con uno de los valores "Técnico", "Marketing" o "Administrativo". (Pista: puede usar la expresión {{ $random.int(0, 2) }} para generar un entero aleatorio y mapearlo a un valor).

  5. Use un nodo Switch para enrutar las tareas según su priority (tres salidas: "Alta", "Media", "Baja").

  6. Para cada rama de prioridad:

    • Use otro nodo Switch anidado para enrutar la tarea según su type (tres salidas: "Técnico", "Marketing", "Administrativo").

    • Escriba la tarea en una hoja de cálculo específica. Por ejemplo, una tarea de prioridad "Alta" y tipo "Técnico" iría a una hoja llamada "Tareas_Tecnicas_Alta". Deberá crear las 9 hojas correspondientes a las combinaciones.

  7. Use un nodo Merge en modo Append para unir todas las ramas finales.

  8. Después del Merge, use un único nodo Google Sheets para añadir una entrada a una hoja de log llamada "Registro_General" que contenga la activity, priority, type y la hora_asignacion (use {{ $now }}).

4.4. Ejercicio 4: Repositorios de GitHub por Lenguaje (Dificultad: Media)

Objetivo: Crear un flujo de trabajo que obtenga la lista de repositorios de una organización de GitHub, los clasifique por lenguaje de programación usando un nodo Switch con salida default, y los guarde en hojas separadas de un documento de Google Sheets.

API a utilizar: GitHub API (gratuita, sin clave para uso básico): https://api.github.com/orgs/{org}/repos?per_page=30 (sustituya {org} por el nombre de una organización, por ejemplo google o microsoft).

Requisitos:

  1. El flujo de trabajo debe iniciarse con un Manual Trigger.

  2. Use un HTTP Request para obtener los repositorios de la organización elegida.

  3. Use un Split Out sobre el array de repositorios para procesar cada uno individualmente.

  4. Use un nodo Switch en modo Rules con el Routing Field {{ $json.language }} para clasificar los repositorios:

    • Salida 0: is equal to JavaScript

    • Salida 1: is equal to Python

    • Salida 2: is equal to C++

    • Salida default: para todos los demás lenguajes (incluyendo null si el repositorio no tiene lenguaje definido).

  5. Cree un Google Sheet con cuatro hojas: JavaScript, Python, C++ y Otros.

  6. Escriba los repositorios en la hoja correspondiente, incluyendo al menos las columnas Nombre, Lenguaje, Estrellas (stargazers_count) y Última Actualización (updated_at).

  7. Pregunta de reflexión: ¿Qué pasaría si la organización no tiene ningún repositorio en Python? ¿Se ejecutaría la rama correspondiente? Investigue cómo se comporta un nodo Switch cuando una de sus salidas no recibe ítems.

4.5. Ejercicio 5: Pronóstico del Tiempo con Transformación de Datos (Dificultad: Media-Alta)

Objetivo: Crear un flujo de trabajo que obtenga el pronóstico del tiempo a 5 días, transforme la estructura de datos de la API (arrays paralelos) a un formato procesable, clasifique cada día por tipo de tiempo y guarde el resultado en Google Sheets.

API a utilizar: Open-Meteo (gratuita, sin clave API): https://api.open-meteo.com/v1/forecast?latitude=40.4168&longitude=-3.7038&daily=weather_code,temperature_2m_max&timezone=auto&forecast_days=5 (coordenadas de Madrid).

Requisitos:

  1. El flujo de trabajo debe iniciarse con un Manual Trigger.

  2. Use un HTTP Request para obtener el pronóstico. Observe que la respuesta contiene un objeto daily con arrays paralelos (time, weather_code, temperature_2m_max), no un array de objetos.

  3. Añada un nodo Code (tipo JavaScript) que transforme los arrays paralelos en un array de objetos, uno por día. Cada objeto debe tener las propiedades fecha, codigo y temp_max. (Pista: use un bucle for sobre el índice del array time y construya un objeto con daily.time[i], daily.weather_code[i] y daily.temperature_2m_max[i]).

  4. Use un Split Out sobre el array de objetos generado por el nodo Code.

  5. Use un nodo Switch en modo Rules con el Routing Field {{ $json.codigo }} para clasificar cada día:

    • Salida 0 ("Despejado"): is less than or equal to 1

    • Salida 1 ("Nublado"): is greater than 1 y is less than or equal to 3 (dos condiciones con AND)

    • Salida 2 ("Lluvia"): is greater than or equal to 51 y is less than or equal to 67 (dos condiciones con AND)

    • Salida default: para el resto de códigos (nieve, tormentas, etc.).

  6. Cree un Google Sheet con cuatro hojas: Despejado, Nublado, Lluvia y Otro.

  7. Escriba cada día en la hoja correspondiente, incluyendo las columnas Fecha, Código WMO, Temperatura Máx (°C) y Categoría.

  8. Pregunta de reflexión: Investigue la tabla de códigos WMO (World Meteorological Organization) y añada una quinta salida al Switch para los días con nieve (códigos 71-77).

4.6. Ejercicio 6: Combinación de Datos por Posición (Dificultad: Alta)

Objetivo: Crear un flujo de trabajo que obtenga datos de dos APIs diferentes en paralelo y los combine posición a posición usando el nodo Merge en modo Combine by Position, para generar un "plan de día" que incluye un chiste y una actividad.

APIs a utilizar: . JokeAPI: https://v2.jokeapi.dev/joke/Programming?type=single&amount=5 . Bored API: https://bored-api.appbrewery.com/filter?number=5

Requisitos:

  1. El flujo de trabajo debe iniciarse con un Manual Trigger.

  2. Añada dos nodos HTTP Request conectados en paralelo al Manual Trigger: uno para la JokeAPI y otro para la Bored API.

  3. Añada un Split Out a la salida de cada HTTP Request (campo jokes para la JokeAPI; el array de la Bored API para la otra).

  4. Añada un nodo Merge en modo Combine by Position y conecte las salidas de ambos Split Out a las dos entradas del Merge. El primer chiste se combinará con la primera actividad, el segundo con la segunda, y así sucesivamente.

  5. Añada un nodo Edit Fields (Set) después del Merge que cree un campo plan combinando el chiste ({{ $json.joke }}) y la actividad ({{ $json.activity }}) en un único texto.

  6. Escriba los planes en una hoja de Google Sheets llamada "Planes", con las columnas Chiste, Actividad y Plan.

  7. Pregunta de reflexión: ¿Qué pasaría si una de las APIs devolviera menos de 5 elementos? Investigue cómo se comporta el modo Combine by Position cuando las dos entradas tienen un número diferente de ítems.

4.7. Ejercicio 7: Informe Diario de Productos (Dificultad: Muy Alta)

Objetivo: Crear un flujo de trabajo completo y autónomo que se ejecute una vez al día, obtenga todos los productos de la Fake Store API, los clasifique por rango de precio, los consolide en un único flujo y genere un informe en una sola hoja de Google Sheets. Este ejercicio combina todos los conceptos de la práctica en un único pipeline.

API a utilizar: Fake Store API (https://fakestoreapi.com/products)

Requisitos:

  1. El flujo de trabajo debe iniciarse con un Schedule Trigger que se ejecute una vez al día (a las 8:00 AM).

  2. Use un HTTP Request para obtener todos los productos.

  3. Use un Split Out para procesar cada producto individualmente.

  4. Use un nodo Switch en modo Rules con el Routing Field {{ $json.price }} para clasificar los productos en tres rangos:

    • Salida 0 ("Económico"): is less than 50

    • Salida 1 ("Medio"): is greater than or equal to 50 y is less than or equal to 200 (dos condiciones con AND)

    • Salida 2 ("Premium"): is greater than 200

  5. En cada rama, añada un nodo Edit Fields (Set) que cree un campo categoria con el valor correspondiente ("Económico", "Medio" o "Premium").

  6. Use un nodo Merge en modo Append para consolidar las tres ramas en un único flujo.

  7. Después del Merge, use un único nodo Google Sheets para escribir todos los productos en una hoja llamada "Informe_Diario", incluyendo las columnas ID, Título, Precio, Categoría y Fecha del Informe (use {{ $now }}).

  8. Active el flujo de trabajo y verifique que se ejecuta correctamente a la hora programada.

  9. Pregunta de reflexión: ¿Cómo modificaría este flujo para que, en lugar de escribir todos los productos en una sola hoja, escribiera un resumen (número de productos por categoría) en una hoja separada? Investigue el nodo Aggregate o el uso de un nodo Code para calcular agregados.

5. Conclusiones y Avance de la Próxima Práctica

Con esta práctica, hemos cruzado un umbral importante. La capacidad de autenticarse con servicios externos, combinada con el enrutamiento y la fusión de datos, nos permite diseñar flujos de trabajo que modelan procesos de negocio reales y complejos. Hemos aprendido a gestionar la lógica de múltiples casos con el nodo Switch, a consolidar resultados con Merge y, lo más importante, a persistir nuestros datos en un sistema externo como Google Sheets.

En la próxima práctica, nos centraremos en la robustez y la modularidad de nuestros flujos de trabajo, introduciendo dos conceptos clave para la creación de automatizaciones a gran escala:

  • Manejo de Errores: Se presentará el Error Trigger y el nodo Stop and Error. Aprenderemos a construir flujos de trabajo de "manejo de errores" dedicados que se activan cuando un flujo principal falla, permitiéndonos enviar notificaciones, registrar el error y tomar acciones correctivas.

  • Sub-flujos de Trabajo (Sub-workflows): Se introducirán los nodos Execute Workflow y Execute Workflow Trigger. Aprenderemos a encapsular lógica reutilizable en flujos de trabajo secundarios que pueden ser llamados desde un flujo principal, promoviendo un diseño limpio, modular y fácil de mantener.
